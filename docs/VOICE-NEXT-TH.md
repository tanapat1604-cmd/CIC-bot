# ขั้นต่อไป: CIC ฟังและตอบภาษาไทยในเครื่อง

สถานะล่าสุด 9 ตุลาคม: ติดตั้งเสียงตอบ/ตัวถอดเสียงแล้ว เสียงตัวอย่างผู้ใช้ยอมรับสำหรับทดลอง แต่ไมค์จริงถอดคำผิด (“ตัวตัวตัว in it”) และผู้ใช้แจ้งเตือนไมค์เบาในรอบถัดมา เพิ่มเลือกไมค์ SP-07/ระดับเสียง/beam 5 และแก้การเฉลี่ยความดังรวมช่วงเงียบแล้ว ยังรอไมค์จริงทดสอบหลังแก้ ไม่ผ่าน hands-free ข้อความ “ยังไม่ติดตั้ง/ยังไม่มีไมค์จริง” ในบันทึกเก่าด้านล่างเป็นประวัติ ให้ยึดผลล่าสุดใน `validation/2026-10-09-voice/RESULTS.md`.

## สิ่งที่ตรวจจริงวันนี้

ตรวจเสียงที่ Windows SAPI คืนผ่าน GetInstalledVoices โดยไม่เปิดไมโครโฟนและไม่สั่งพูด: พบ Microsoft David Desktop, Zira Desktop, David, Mark และ Zira ทั้งหมด en-US. ยังไม่มีหลักฐานว่าเสียงไทยที่เรียกจาก CIC ใช้งานได้ การตรวจนี้ไม่ครอบคลุมเสียงจากทุก API/บริการ cloud และไม่ใช่การทดสอบคุณภาพเสียงหรือการฟังไมโครโฟน

งานเปิดเพลงผ่าน CIC มีช่องคำสั่ง แผนโมเดล การอนุญาตหนึ่งงาน ตัวควบคุม browser และตัวตรวจผลแล้ว ระบบเสียงควรส่งข้อความที่ถอดได้เข้าทางนี้ และอ่านผลที่ตรวจแล้วกลับ ไม่ให้ ASR หรือ TTS สร้างสิทธิ์ใหม่เอง

## ตัวเลือกที่เสนอให้ทดลอง

1. เริ่ม TTS ด้วยเสียง Windows Thai Pattara ถ้าติดตั้งและ API ของ CIC มองเห็น: เป็นเสียงไทยที่ Microsoft ระบุไว้ในรายการ รองรับการใช้เสียงในเครื่อง แต่ต้องตรวจ runtime Windows10 เครื่องนี้และฟังจริงก่อนถือว่าผ่าน [รายการเสียง Microsoft](https://support.microsoft.com/en-us/accessibility/windows/narrator/appendix-a-supported-languages-and-voices)
2. ASR ในเครื่อง: faster-whisper พร้อมโมเดล multilingual ขนาด base เป็นจุดเริ่มต้น ใช้ CPU/int8 และไม่เกิน3threads ทดลองคำสั่งไทยจริงก่อนเลือก small. รุ่น .en ไม่เหมาะกับภาษาไทย. README รองรับ CPU int8; ตัวเลข benchmark ของโครงการไม่ใช่ผลวัด i5-7500 เครื่องนี้ [faster-whisper](https://github.com/SYSTRAN/faster-whisper), [Whisper และรายการโมเดล](https://github.com/openai/whisper)
3. TTS ทางเลือก: Piper Thai tsync2 medium มี model card และต้องใช้ Piper>=1.8. ข้อมูลชุดเสียงระบุ non-commercial; ต้องตรวจ license ของ runtime/weights/dataset และการใช้ของ CIC ก่อนเลือกเพื่อเผยแพร่แอป. ยังไม่ได้โหลดหรือทดสอบเสียงนี้ [model card](https://huggingface.co/rhasspy/piper-voices/blob/main/th/th_TH/tsync2/medium/MODEL_CARD), [runtime](https://github.com/OHF-Voice/piper1-gpl)

ลำดับที่เสนอเป็นข้อสรุปสำหรับการทดลองจากเอกสารและข้อจำกัด RAM/CPU ไม่ใช่ผลรับรองเสียงไทย ไม่ใช้ browser ASR ที่ส่งเสียงไปบริการภายนอกเป็นค่าเริ่มต้น

## ขอบเขตงานเสียงที่ตรวจรับได้

- แยกสถานะ mic permission, recording, transcribing, transcript review, plan review, execution, speaking และ stopping. ผู้ใช้เริ่มฟังครั้งแรกเองและเห็นไฟฟังชัดเจน ห้ามเปิดไมค์ด้วยการโหลดหน้า
- บันทึกเสียงสั้นใน RAM มี VAD/ระยะสูงสุด/timeout และปิด mic track จริงเมื่อหยุดหรือออกจากหน้า ไม่บันทึกไฟล์ถาวรหรือส่งภายนอกโดยปริยาย
- บน8GB ให้ ASR/qwen/browser งานหนักเข้า scheduler เดียวกัน ทดลอง unload และวัด RAM ทั้ง pipeline. หลังอัปแรมต้องวัดใหม่ ไม่สรุปว่า CPU เร็วขึ้นจาก RAM
- เสียง “อนุญาต” ต้องผูกกับงาน/แผน/nonce ที่กำลังรอ เพียงคำว่าอนุญาตจากเสียงเพลงหรือ TTS ห้ามใช้เป็น grant. งานอันตราย/การส่งข้อความ/บัญชี/ไฟล์ต้องตรวจแยก
- ตอบกลับจากผลเครื่องมือที่ตรวจแล้ว เช่น “เปิดเพลงแล้ว” หลัง main video เล่น; หากยังแสดงโฆษณาหรือ CAPTCHA ให้บอกสถานะตามจริง
- จัดการเสียงสะท้อน: ไม่ตีเสียง TTS หรือ YouTube เป็นคำสั่งผู้ใช้; ทดสอบหูฟัง/ลำโพง/ไมค์จริง การ mute ชั่วคราวต้องคืนเฉพาะค่าในหน้าต่างที่ CIC เป็นเจ้าของ
- การหยุดต้องคืนทั้ง capture, ASR worker, TTS playback และ browser/action ที่ผูกไว้ มีช่องหยุดอิสระ และไม่อ้างว่าหยุดแล้วจากการ abort HTTP เพียงอย่างเดียว

## เกณฑ์ก่อนอ้างว่าไม่ต้องแตะเมาส์/คีย์บอร์ด

ผู้ใช้อนุญาตไมค์และขอบเขตหนึ่งรอบ จากนั้นพูดคำสั่งอย่างน้อย10กรณี แยกเสียงเงียบ/คำไทย/ชื่อศิลปิน/ปฏิเสธ/ยืนยัน/หยุด. รวม “เปิดเพลงยังโอมล่าสุดให้หน่อย”, “ไม่อนุญาต”, เสียงคำว่าอนุญาตจากเพลง และกรณีโฆษณา/CAPTCHA. ต้องทดสอบตั้งแต่เสียงจริงถึงการตรวจหน้าเว็บและการตอบเสียงจริง ไม่ใช้ fixture transcript หรือการกดของ Codex เป็นหลักฐานว่ามันฟังเสียงเองแล้ว

รายงาน WER/CER หรือ transcript errors รายกรณี, คำสั่งที่ตีความถูก/ผิด, unauthorized actions, stop latency, เวลารวม และ sampled RAM พร้อมข้อจำกัดของ sampling. ถ้ายังต้องพิมพ์/กดในขั้นอนุญาต ให้ระบุว่าเป็น voice-assisted ไม่ใช่ hands-free acceptance

รอบนี้ยังไม่ได้ติดตั้ง voice pack/ASR/TTS model ไม่เปิดไมค์ และไม่มีผลเสียงไทยสองทางให้รับรอง

## บทสนทนาเป้าหมายที่ผู้ใช้ยืนยัน

หลังอนุญาตไมค์และขอบเขต Chrome ครั้งแรก ผู้ใช้พูด “เฮ้ CiC เปิดเพลงยังโอมล่าสุดให้หน่อย” (รับรูปสะกด “เห้ ci” จาก ASR เป็น wake phrase ได้เมื่อทดสอบจริง). CIC ตอบเสียงไทย “ได้ครับท่าน กำลังหาเพลงล่าสุดให้ครับ” แล้วส่งคำสั่งผ่านตัวตรวจและ BrowserAgent เดิม. เมื่อพบและตรวจ main video เล่นจริง จึงพูด “เปิดให้แล้วครับท่าน” พร้อมชื่อเพลง. หากยังโฆษณา/ไม่มีศิลปิน/RAM ไม่พอ ให้ตอบสถานะและถามเฉพาะสิ่งที่ขาด ไม่ตอบสำเร็จล่วงหน้า.

เกณฑ์นี้ต้องมีหลักฐานจากไมค์จริงและ TTS ไทยจริง โดยไม่มี Codex พิมพ์ transcript หรือคลิกอนุญาตแทนในช่วง acceptance. วัดเวลา wake→ack→model→tool→verified feedback และ stop latency; เพลงหรือ TTS ของ CIC ต้องไม่สร้างคำสั่ง/สิทธิ์เอง. ทดสอบพูดหยุดทั้งระหว่างค้นและเล่น พร้อมปุ่มหยุดอิสระ. ถ้าตอบรับครั้งแรกหรือปุ่มพูดยังต้องกดทุกคำสั่ง ให้ระบุข้อจำกัดตามจริง.

เป้าหมายดูทั้งจอและทำงานในแอปจริงให้แยกจาก browser command: ทำ native broker ที่ยืนยันหน้าต่าง/โปรเซส/ขอบเขตของแอปที่ผู้ใช้อนุญาตก่อน input ทุกครั้ง มี focus/geometry/modifier checks และตรวจผลหลังทำ. ขยายจาก Notepad/YouTube ไป Chrome และแอปอื่นทีละ acceptance; ไม่เปิด arbitrary shell หรือใช้ debugger อ่านโปรไฟล์ส่วนตัว. ปัจจุบันการส่งเพลงไป Chrome ปกติรับรองเพียง launch request + window inventory; ยังไม่มี controller อ่าน/สั่งต่อในหน้าต่างนั้น.
