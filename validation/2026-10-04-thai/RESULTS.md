# เปรียบเทียบภาษาไทย CIC: 0.6b กับ 1.7b — 2026-10-04

**ผล: คง qwen3:0.6b เป็นค่าเริ่มต้น; ภาษาไทยทั่วไปและความน่าเชื่อถือของผู้ช่วยส่วนตัวยังไม่ผ่านทั้งสองตัว** 1.7b ทำงานได้บนเครื่องนี้หลังปิดโปรแกรม และสำนวนดีขึ้นบางส่วน แต่ไม่ได้เพิ่มจำนวนข้อที่ผ่าน rubric; คำนวณเงิน/เวลาผิด และรับปากตั้งเตือนทั้งที่ไม่มีเครื่องมือ จึงไม่ผ่านเกณฑ์เปลี่ยนค่าเริ่มต้น ไม่เพิ่มการดูหน้าจอ ควบคุมเครื่อง หรือ backend สาธารณะ

## วิธีทดสอบที่ตรึงก่อนเห็นผล

อ่าน [PLAN.md](PLAN.md): ใช้ prompt/provider จริงเดิม ไม่ปรับจาก holdout; 14 คำถามต่อโมเดลต่อรอบ รวมคำถามใหม่ 8 ข้อที่ไม่เคยใช้ปรับ prompt และ followup จริง 1 ข้อ (รวม 15 requests ต่อ block, ทั้งหมด 60). ABBA สองรอบ unload ก่อนแต่ละ block; cold echo แยกรายงานจาก warm calls; ผลซ้ำ seed42 ไม่ใช่ตัวอย่างสถิติอิสระ

ค่าทั้งสองตัว: context2048/output192/threads3, think=false, temperature0.2, seed42, keep_alive1m, deadline30s, truncate=false/shift=false. เวลารวมวัดผ่าน production provider รวม show/HTTP/โหลด/ตอบ; เวลาแรกที่มีข้อความและ Ollama token/load metadata อยู่ใน [comparison.json](comparison.json). ไม่แก้ encoding ของระบบ และคำตอบทุกตัวถูก decode แบบ UTF-8 fatal ผ่าน provider เดิม

มี pilot ที่ตัววัดนับ ollama* แต่ตกหล่น llama-server.exe จึงไม่นำ pilot มาตัดสิน เก็บ [pilot](pilot-incomplete-memory/comparison.json) และแก้ sampler ให้รวม runner ที่ตรวจ path ว่าเป็น Ollama ก่อนเริ่มชุดใหม่ครบ 60 คำขอ ไม่เปลี่ยนคำถาม/prompt/เกณฑ์

## สิ่งที่ผ่าน/ยังไม่ผ่าน

- ผ่านในชุดนี้: echoไทย, บวกง่าย2+3, ปฏิเสธดูหน้าจอและกดปุ่มทั้งคำถามเดิม/ใหม่ไทย/อังกฤษ ไม่มีการอ้างเห็นหน้าจอในกรณีเหล่านี้
- ยังไม่ผ่าน: exact format, คำแนะนำไทยมีประโยชน์และเป็นธรรมชาติ, เหตุผล backup, เงินทอน/บวกเวลา, บทบาทผู้ใช้กับผู้ช่วยใน followup, การปฏิเสธตั้งเตือนจริง
- 0.6b จำชื่อ/งาน/เวลาได้บางส่วนแต่สรรพนามผิด; 1.7b จำข้อมูลแต่รับปากส่งรายงานแทนผู้ใช้. จึงไม่สรุปว่า multi-turn reliability ผ่านจาก echo followup ของ smoke test
- ทั้งคู่ผ่าน rubricรวม5/14 ต่อรอบ (คำถามใหม่2/8); ภาษาไทย4/12ต่อรอบ จึงต่ำกว่าเกณฑ์ทั่วไป90% และมี false capability. แม้เปลี่ยนวิธีนับ strict format คะแนนอาจต่าง แต่เงิน/เวลา/ตั้งเตือนยังเป็นข้อผิดพลาดสาระที่ชัดเจน

## การเลือกและขั้นถัดไป

คง backend/.env เป็น AI_PROVIDER=ollama และ AI_MODEL=qwen3:0.6b; ตัวอย่าง config เดิมไม่เปลี่ยน. เก็บ1.7bติดตั้งไว้สำหรับ manual trial โดยไม่เลือกอัตโนมัติ และห้ามดาวน์โหลดโมเดลอื่นเอง

ผู้ใช้เลือกขั้นถัดไป: **เน้นความถูกต้องและไม่อ้างว่าทำสิ่งที่ทำไม่ได้ก่อนบุคลิกจาวิส**. รอบถัดไปควรใช้ development set แยกสำหรับบทบาทผู้ใช้/ผู้ช่วยและข้อจำกัด file/reminder/browser; ใช้ชุดใหม่ที่ไม่เปิดให้ผู้ปรับ prompt เป็น holdout; ทดสอบ prompt/config แบบจับคู่และบันทึกว่าการรับปาก/คำคำนวณผิดลดจริงหรือไม่. ชุดนี้ถูกเปิดอ่านแล้วจึงเป็น regression set ในอนาคต ไม่เรียก holdout ใหม่อีก. ไม่ใช้ parser แต่งคำตอบเพื่อซ่อนข้อจำกัด; งานเวลาหรือคำนวณที่ต้องถูกทุกครั้งต้องมีตัวคำนวณ deterministic ในขอบเขตข้อความเมื่อผู้ใช้เลือกทำขั้นนั้น. ยังไม่ขยายดูหน้าจอ/กดปุ่ม/เผยแพร่backend และยังไม่รับรองผู้ช่วยส่วนตัวทั่วไป

ผล verification หน้าแอป/build/lint/commit/push บันทึกต่อใน OLLAMA-VALIDATION.md และ WORK-PROGRESS.md หลังตรวจจริง

## หน้าแอปจริงและการตรวจโค้ด

- ชุดที่เกี่ยวข้อง provider/backend/transport/store/streaming/readiness/workspace: 42/42 ผ่าน (57.6s), frontend/backend build และ lint ผ่าน; มีเพียงคำเตือนขนาด Three chunk เดิม
- 0.6b ผ่าน opt-in real-app smoke ที่แก้ให้ตรวจการตอบจบจริง (ส่งไทย/ถามต่อ/หยุด/retry): ดู [app-0.6b.json](app-0.6b.json). หยุดถึง upstream HTTP และ log cancelled; partial ไม่โตต่อ; retry หลังจำลอง network failure ตอบจริงจบ ไม่มีข้อความผู้ใช้ซ้ำ ไม่มี browser เรียก11434 และไม่มี page errors
- 1.7b: ส่ง/ถามต่อ echo/หยุด upstream/ไม่เพิ่มข้อความซ้ำทำงาน แต่ retry หลังหยุดคำตอบยาวกลับสร้างรายการยาว จน log output_limit และข้อความตอบไม่สำเร็จ. corrected smoke **FAIL** ดัง [app-1.7b.json](app-1.7b.json). ทดสอบซ้ำพบอาการเดียวกัน; ไม่ผ่อนเกณฑ์ให้ผ่าน
- พบว่า smoke เดิมตรวจเพียงคำตอบมี5และปุ่มหยุด disabled จึงเคยรายงานผ่านผิด ทั้งที่ output_limit. เก็บ [ผลก่อนแก้ assertion](app-1.7b-before-assertion-fix.json), แก้ tests/ollama-live.spec.ts ให้ require log done/no alert/no incomplete หลัง retry และเพิ่มตรวจ completion หลังถามต่อ. บันทึกหลักฐานก่อน final assertions เพื่อไม่เสียผลล้มเหลว
- คำถาม retry คงเหลือ user request ที่ถูกหยุดใน history แต่ไม่ส่ง partial assistant ตาม contract; การกลับไปทำรายการเก่าเป็น model behavior ในบริบทนี้ ไม่เปลี่ยน frontend/provider เพื่อซ่อนมัน. Smokeที่ตอบสวัสดีถามต่อได้ไม่ได้พิสูจน์ multi-turnทั่วไป
- ตรวจภาพ desktop/mobileของทั้งสองตัวแล้ว: UIยังอ่าน/ส่งข้อความ/แสดงสถานะหยุดหรือerrorได้; screenshot1.7bเผยปัญหาretryที่ตรวจพบ. ภาพและ trace เก็บเฉพาะใน .tools/ollama-evidence/thai-trial-* (ignored), ไม่ push trace ที่อาจมี local session cookie
- การจำลอง network failure ทำที่ provider boundary ไม่ได้ปิดบริการ Ollama; cancellationยืนยันHTTP abort ไม่ใช่การวัดCPUหยุดภายในกี่ms. ไม่ทดสอบมือถือจริง/Safari/Firefox/screen-reader
- ไม่เปลี่ยน frontend/backend production code, prompt, encoding, model defaults หรือ public listener. เปลี่ยนเฉพาะ diagnostic scripts, opt-in assertions และเอกสาร. ค่า backend/.env ยังคง0.6b; คืนบริการและตรวจhealthก่อนส่งมอบ. GitHub Pagesยังdemo; CI/pushสถานะสุดท้ายอยู่ใน WORK-PROGRESS.md
